# Earth Under Decision — Team NON-HUMAN

منصة استكشاف بيانات رصد الأرض ودعم الفهم البيئي. الحزمة الحالية تربط React/Vite بالـFastAPI API وتضم البيانات التي أرسلها الفريق لعام 2023، مع توضيح حالة التحقق والقيود.

## تشغيل الموقع بدون VS Code (Windows)

1. نزّل وثبّت [Docker Desktop](https://www.docker.com/products/docker-desktop/).
2. افتح Docker Desktop وانتظر حتى تظهر حالة **Engine running**.
3. فك ضغط المشروع كاملًا في مجلد عادي على جهازك.
4. افتح مجلد `earth-under-decision` ثم اضغط مرتين على `START_EARTH_UNDER_DECISION.bat`.
5. أول تشغيل يبني الحاويات ويجهّز PostgreSQL/PostGIS ويطبق migrations ثم يفتح الموقع تلقائيًا.
6. افتح الموقع يدويًا عند الحاجة: `http://localhost:8000`، وتوثيق الـAPI: `http://localhost:8000/docs`.
7. لإيقاف الموقع اضغط مرتين على `STOP_EARTH_UNDER_DECISION.bat`. هذا الأمر لا يحذف قاعدة البيانات أو ملفاتك.

**مهم:** أول تشغيل يحتاج اتصال إنترنت لتنزيل Docker images وNode/Python dependencies. لا تحتاج فتح VS Code في التشغيل اليومي.

## ملف البيئة `.env`

الحزمة تتضمن `.env` بعناصر وهمية فقط. لا توجد كلمات مرور أو NASA tokens حقيقية. القيم الحالية `CHANGE_ME...` لا تصلح للنشر العام.

للتشغيل المحلي في Docker Compose، يمكن ترك placeholders كما هي للتجربة المحلية فقط. قبل فتح المشروع على الإنترنت:

- غيّر `POSTGRES_PASSWORD` إلى كلمة مرور طويلة وعشوائية.
- غيّر `ADMIN_API_TOKEN` إلى قيمة طويلة وعشوائية. استخدم قيمة Hex/حروف وأرقام لتجنب مشاكل الرموز الخاصة في ملف البيئة.
- لا ترسل القيم الحقيقية في المحادثة ولا تضف `.env` إلى GitHub.
- لا تضع NASA credentials أو `ADMIN_API_TOKEN` في `VITE_` variables أو ملفات الواجهة.
- عمليات الرفع والإدارة محمية؛ وهي معطلة مع قيمة `CHANGE_ME` حتى تضبط `ADMIN_API_TOKEN` بنفسك.

` .env ` مستثنى من Git عبر `.gitignore`، بينما `.env.example` مسموح رفعه لأنه لا يحتوي أسرارًا.

## ما الذي تحتويه البيانات الحالية؟

| المصدر / المتغير | ما وصل من الفريق | الحالة والاستخدام في الموقع |
|---|---|---|
| NASA GLDAS Noah 2.1 `Evap_tavg` | ملف 3-hourly لنقطة شبكة قرب 30.9°N, 31.0°E، تمت معالجته إلى 365 يومًا | يعرض كمخرجات نموذجية عند نقطة واحدة، وليس استهلاك ري فعليًا أو متوسطًا للدلتا |
| NASA GLDAS Noah 2.1 `RootMoist_inst` | نفس النقطة والفترة؛ 8 خطوات كل يوم | متوسط/حدود رطوبة منطقة الجذور من نموذج GLDAS، وليست قراءة مستشعر حقلي |
| NASA GPM `GPM_3IMERGM` v07 | GeoTIFF بدقة شبكة 0.1°، 540 خلية، معدل متوسط زمني `mm/hr` على 2023 | الخريطة تعرض مراكز خلايا GPM؛ `mm/year` هو **مكافئ سنوي مشتق من المعدل × 24 × 365**، وليس مجموعًا يوميًا مباشرًا |
| NOAA GHCN-Daily | 11 محطة، ومرجع حرارة الإسكندرية متاح في 219 يومًا حتى 2023-08-09 | مقارنة خارجية اختيارية؛ NOAA ليس NASA، ولا يدخل ضمن مؤشرات NASA الأساسية |
| NDVI `MOD13Q1.061` | لم يصل ملفه | يظهر كغير متاح، ولا توجد قيم مخترعة |
| LST `MOD11A2.061` | لم يصل ملفه | يظهر كغير متاح، ولا توجد قيم مخترعة |

تفاصيل الأرقام والمنهج موجودة في `docs/README_storytelling_AR.md` ونتائج فحص الجودة في `seed_data/processed/qc_report_2023.json`.

## ملاحظات علمية قبل العرض

- بيانات GLDAS نقطة نموذجية واحدة وليست متوسطًا مكانيًا لدلتا النيل.
- قيم التبخر-نتح منخفضة مقارنة بالواقع الزراعي لأن مخرجات GLDAS لا تمثل استهلاك الري الفعلي في أراضي الدلتا؛ لذلك توصف بأنها الاستجابة الطبيعية المُنمذجة.
- GPM المُسلّم هو `GPM_3IMERGM` monthly v07 time-mean rate، وليس ملف `GPM_3IMERGDF` daily. المكافئ السنوي مشتق رياضيًا من المعدل ولا يُعرض كجمع يومي أصلي.
- الحرارة من NOAA وليست NASA، وتغطيتها ناقصة؛ القيم الغائبة بقيت فارغة ولم تتحول إلى صفر.
- سنة واحدة تسمح بوصف الموسم داخل 2023 فقط؛ لا نقدم منها اتجاهًا مناخيًا طويل الأمد أو دلالة إحصائية أو توقعًا مستقبليًا.
- لم تُرسل حدود إدارية موثقة؛ لذلك لا يرسم الموقع حدود محافظات مفترضة. نقاط الخريطة هي مراكز خلايا GPM ونقطة GLDAS فقط.
- لا توجد حتى الآن ملفات NDVI أو LST؛ لا تعرض الواجهة نتائج مصطنعة لهما.

## ما الذي يعمل في الموقع؟

- Landing Page عربية افتراضيًا مع English وRTL/LTR.
- Dashboard متصل ببيانات 2023 عبر API ويعرض مؤشرات GLDAS وGPM المتاحة.
- Explore Map يعرض شبكة مراكز خلايا GPM الحقيقية على خريطة أساس مرجعية، ونقطة GLDAS. خريطة الأساس ليست منتج NASA.
- Trend page تعرض النمط الشهري داخل 2023؛ لا تحسب اتجاهًا طويل الأمد أو دلالة إحصائية.
- What-If يخزن الافتراضات فقط ويظل Illustrative Only؛ لا يوجد نموذج تنبؤ.
- Methodology & Data Sources تعرض سجل المصادر والقيود.
- FastAPI يوفر endpoints للملخص، السلسلة الشهرية واليومية، شبكة المطر، والكتالوج، إضافة إلى بقية endpoints العامة.

## إعادة تشغيل التنظيف

الملفات الأصلية محفوظة داخل `seed_data/raw/` في نسخة النشر، والنتائج النظيفة داخل `seed_data/processed/`. ملف `scripts/clean_data_original_uploaded.py` نسخة محفوظة من سكريبت التنظيف الذي رفعه الفريق دون تعديل. ملف `scripts/clean_data.py` هو إصدار قابل لإعادة التشغيل على أسماء الملفات الفعلية الموجودة في `data/raw/` ويكتب المخرجات في `data/processed/`.

الحزمة تحتفظ بملفات البيانات المخصصة للنشر داخل `seed_data/`، ولا تضع نسخة العمل المحلية `data/` داخل Git. لإعادة تشغيل التنظيف من PowerShell داخل مجلد المشروع، أنشئ نسخة عمل أولًا ثم شغّل السكريبت:

```powershell
Copy-Item -Recurse seed_data data
python -m pip install pandas numpy rasterio
python scripts/clean_data.py
```

إذا كان مجلد `data/` موجودًا بالفعل فلا تنسخ فوقه؛ استخدم نسخة احتياطية أو افحص الملفات أولًا. لا يغيّر السكريبت الملفات الخام. راجع `data/processed/qc_report_2023.json` قبل اعتماد أي مخرجات جديدة. ملفات `seed_data/` هي نسخة الإدخال المضمنة في إصدار النشر؛ لا تستبدلها تلقائيًا من دون مراجعة الجودة.

## الرفع على الإنترنت من خلال واجهة رسومية (بدون VS Code)

المشروع يحتوي `render.yaml` ليتم نشره كـBlueprint على Render: خدمة Docker واحدة تعرض الموقع والـAPI من نفس العنوان، وقاعدة PostgreSQL، وPersistent Disk لملفات الرفع. لا توجد عملية نشر فعلية على حسابك بعد؛ الربط بالحساب يحتاج تنفيذك من لوحة Render.

### أ. رفع نسخة المشروع إلى GitHub Desktop

1. نزّل [GitHub Desktop](https://desktop.github.com/) وثبّته وسجّل الدخول.
2. فك ضغط المشروع في مجلد ثابت.
3. في GitHub Desktop اختر **File → Add Local Repository**. إذا قال إن المجلد ليس Repository، اختر **create a repository** في نفس المجلد (لا تنشئ مجلد مشروع داخليًا جديدًا).
4. راجع قائمة الملفات قبل أول Commit. يجب ألا يظهر `.env` ضمن الملفات المراد رفعها؛ `.env` مستثنى من `.gitignore`. يجب أن يظهر `.env.example`.
5. تأكد أن `seed_data/` موجود ضمن الملفات التي سترفع، بما فيها ملفات البيانات التي يعتمد عليها تشغيل نسخة العرض.
6. اكتب Summary مثل `Initial Earth Under Decision release` ثم اضغط **Commit to main**.
7. اضغط **Publish repository**. يُفضّل اختيار **Keep this code private** إلى أن يراجع الفريق تراخيص البيانات ومحتويات المستودع.

### ب. النشر على Render

1. افتح [Render Dashboard](https://dashboard.render.com/) وسجّل الدخول.
2. اختر **New → Blueprint** أو خيار إنشاء Blueprint من Git repository.
3. اربط GitHub إذا طلب ذلك، واختر مستودع `earth-under-decision`.
4. Render سيقرأ `render.yaml` ويعرض الموارد: Web Service، PostgreSQL، وPersistent Disk. راجع التكلفة والخطة والمنطقة قبل التأكيد.
5. ابدأ إنشاء الموارد وانتظر ظهور Deployment ناجح.
6. افتح رابط `onrender.com` الذي يعرضه Render. جرّب `/health` ثم `/docs`، وبعدها افتح الصفحة الرئيسية وDashboard والخريطة.
7. راجع Environment في Render وتأكد من إنشاء `ADMIN_API_TOKEN` تلقائيًا. لا تحتاج إضافة بيانات NASA سرية الآن لأن مصدر البيانات الموجود مرفوع ضمن `seed_data/`.

لرفع التحديثات لاحقًا: افتح GitHub Desktop، راجع Changes، اعمل Commit ثم **Push origin**. Render ينشر التحديث تلقائيًا عند وصول commit جديد.

**استمرار الملفات:** Render filesystem افتراضيًا مؤقت؛ لذلك خصصنا Persistent Disk على `/app/data`. قاعدة PostgreSQL تخزّن الميتاداتا، والملفات تبقى على القرص الدائم. لا تحذف الـDisk أو قاعدة البيانات عند إعادة النشر.

### التكلفة المتوقعة على Render

وفق صفحة الأسعار التي تمت مراجعتها في نوفمبر 2026، الخطة المستخدمة في `render.yaml` تقارب: Web Service `0.5c-512mb` = **$7/month**، وPostgres `0.1c-256mb` = **$6/month**، وقرص 1GB = **$0.25/month**؛ أي حوالي **$13.25 شهريًا** قبل الضرائب/الباندويث أو أي إضافات. الأسعار قابلة للتغيير؛ راجع [Render Pricing](https://render.com/pricing) قبل الضغط على إنشاء الموارد.

لا أنصح باعتماد قاعدة البيانات المجانية لتخزين مشروع مستمر؛ خطط Render المجانية لها قيود، وقاعدة Postgres المجانية تنتهي بعد مدة محدودة.

## ملفات المساعدة والتشخيص

- حالة الحاويات: `docker compose ps`
- سجلات الويب: `docker compose logs -f web` أو افتح `VIEW_LOGS_EARTH_UNDER_DECISION.bat` بالنقر المزدوج.
- سجلات قاعدة البيانات: `docker compose logs -f db`
- إعادة تشغيل خدمة الويب: `docker compose restart web`
- إيقاف آمن مع الحفاظ على البيانات: `docker compose down`

لا تستخدم `docker compose down -v` إلا إذا كنت تقصد حذف قاعدة البيانات والملفات المحفوظة نهائيًا.

## الاختبارات وحدود التسليم الحالية

- اختبارات Python: **12 passed** في بيئة التنفيذ الحالية.
- Alembic migration: تم تطبيقها على SQLite لاختبار الهيكل فقط؛ لم يتم اختبار اتصال PostgreSQL/PostGIS حقيقي في بيئة البناء الحالية.
- فحص صياغة TSX/TypeScript: لا توجد أخطاء parsing في الملفات الأساسية.
- لم يكتمل `npm install`/Vite production build هنا بسبب عدم توفر اتصال npm registry، ولم يكن Docker مثبتًا في بيئة البناء؛ لذلك لم يتم تنفيذ تشغيل متكامل محليًا أو نشر حي. Docker build سيحتاج الاتصال بالإنترنت في أول عملية بناء على جهازك أو منصة الاستضافة.
- عمليات تنزيل NASA التلقائية، QA product-specific لملفات MODIS، MODIS NDVI/LST، حدود المحافظات الرسمية، COG/TiTiler، والـbackground worker ما زالت مراحل لاحقة وليست مزعومة على أنها مكتملة.
